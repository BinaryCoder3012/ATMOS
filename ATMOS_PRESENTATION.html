The Challenge

The Problem We're Solving

"How can we accurately and securely authenticate field personnel using facial recognition and liveness detection on standard mid-range mobile devices without any active internet connection?"

  • Construction sites, warehouses, and field ops have zero connectivity
  • Photo-spoofing fraud is rampant — static images can fool basic systems
  • Cloud-dependent solutions fail when cell towers are unreachable
  • Model must be ≤ 20 MB, run at < 1 second on 3GB RAM devices
  • Must support diverse Indian demographics and varying outdoor lighting
🚫📶

Key Innovation: The entire neural inference loop runs on a C++ JSI worklet thread — never touching the JavaScript main thread. This means the UI stays at 60 FPS while ML runs in parallel. Model objects are thread-safely "boxed" via NitroModules and "unboxed" inside the worklet.

Anti-Spoofing

Liveness Detection — EAR & MAR

Eye Aspect Ratio (EAR) — Blink Detection

EAR = ( ‖p₂−p₆‖ + ‖p₃−p₅‖ ) / ( 2 × ‖p₁−p₄‖ )

Open eye EAR ≈ 0.25–0.35. During a blink, EAR drops sharply below 0.20. Both eyes averaged for robustness.

Landmark indices: Left eye (33, 133, 158, 159, 145, 153), Right eye (362, 263, 385, 386, 374, 380) — from MediaPipe Face Mesh specification.

Mouth Aspect Ratio (MAR) — Smile Detection

MAR = ‖p_top − p_bottom‖ / ‖p_left − p_right‖

Neutral mouth MAR ≈ 0.2–0.4. A smile pushes MAR above 0.60. Mouth indices: (13, 14, 61, 291).

Challenge Flow

  • App randomly selects "Please Blink" or "Please Smile"
  • User must perform the gesture within 10 seconds
  • Face recognition only starts after liveness is verified
  • Static photos cannot produce dynamic EAR/MAR events
  • Prevents photo spoofing, screen replay, and cardboard cutout attacks

All thresholds are runtime-configurable via the Settings screen without rebuilding the app.

Identity Matching

Cosine Similarity Engine

Similarity(A, B) = (A · B) / ( ‖A‖ × ‖B‖ )
  • Compares live 128-dim embedding vs all stored employee baselines
  • Returns value in [0, 1] where 1.0 = identical
  • Match threshold: 0.85 (configurable)
  • O(N × 128) complexity — executes in < 1ms for 128-dim vectors
  • Zero external dependencies — pure TypeScript, worklet-safe

Privacy: ATMOS never stores face images. Only the 128-dim float vector is persisted — it's mathematically impossible to reconstruct a face from an embedding.

Matching Algorithm

function findBestMatch(liveEmbed, employees, threshold) { let bestScore = 0, bestId = null; for (const emp of employees) { const score = cosineSimilarity( liveEmbed, emp.embedding ); if (score > bestScore) { bestScore = score; bestId = emp.id; } } return bestScore >= threshold ? { id: bestId, score: bestScore } : null; // No match }

Offline → Online

Sync & Conditional Purge Mechanism

❶ Authentication recorded offline → MMKV (syncStatus: 'pending')
↓
❷ NetInfo listener detects network restoration
↓
❸ Batch POST all pending records to AWS API Gateway
↓
❹ Only on HTTP 200 OK → purge records from local MMKV

Safety Guarantee

Records are NEVER deleted from local storage unless the server confirms receipt with a 200 status. On failure, records are marked as failed and automatically retried on next connection.

Data Layer

MMKV — The Offline Database

ATMOS uses react-native-mmkv — Tencent's memory-mapped C++ key-value store. It's ~30× faster than AsyncStorage, fully synchronous (no async/await), and persists across restarts.

Model Training

Training on Diverse Indian Demographics

  • MS-Celeb-1M — Large-scale celebrity face dataset for base pretraining
  • VGGFace2 — 3.31 million images, 9,131 subjects with pose/age variation
  • Indian Face Dataset — Curated dataset of diverse Indian demographics: various skin tones, facial features, and regional diversity
  • LFW (Labeled Faces in the Wild) — Benchmark for unconstrained face recognition accuracy validation
  • Data augmentation: random crop, horizontal flip, color jitter, brightness/contrast variation to simulate harsh sunlight, low light, and shadows

Why Indian Demographics Matter: Most face recognition models are trained primarily on Western faces. ATMOS was specifically validated against diverse Indian facial structures, skin tones, and outdoor lighting conditions typical of Indian construction sites and warehouses.

User Guide

How To Use ATMOS

📝

1. Register Employee

Enter name, employee code, and department. Tap "Register Baseline Embedding" → Camera captures face → 128-D vector stored in MMKV.

🛡️

2. Liveness Challenge

App randomly prompts "Please Blink" or "Please Smile". User must perform the gesture within 10s. This proves the face is live, not a photo.

🔐

3. Face Recognition

After liveness passes, MobileFaceNet generates a live embedding. Cosine similarity compares it against all stored baselines. Match ≥ 0.85 = success.

💾

4. Offline Logging

Attendance logged instantly to MMKV with 'pending' status. Works with zero internet. Record includes timestamp, method, and similarity score.

☁️

5. Auto Sync

When WiFi/LTE is restored, NetInfo triggers batch POST to AWS. Records purged ONLY on HTTP 200 confirmation. Zero data loss guaranteed.

⚙️

6. Settings

Admins can tune EAR/MAR thresholds, similarity threshold, and AWS endpoint at runtime. No rebuild required — changes persist via MMKV overrides.

Innovation Highlights

What Makes ATMOS Different

⚡ C++ JSI Worklet Architecture

Unlike traditional RN apps that serialize camera frames over an async bridge (causing drops and lag), ATMOS runs the entire ML pipeline on a C++ worklet thread. The UI thread never blocks — 60 FPS guaranteed.

🧊 INT8 Quantization

Post-training quantization compresses both models from ~20 MB (FP32) to ~7.7 MB (INT8) — a 61% reduction — while maintaining >95% accuracy. Calibrated on Indian face samples for optimal quantization ranges.

🔒 Conditional Purge Safety

Most sync systems delete local data immediately after a POST. ATMOS waits for explicit HTTP 200 confirmation. Crash-safe, network-failure-safe, audit-trail-safe.

🎯 Dual Anti-Spoofing

Two independent liveness methods (EAR blink + MAR smile) randomly selected per session. A static photo cannot produce dynamic EAR events. Video replay is mitigated by random challenge selection.

⚙️ Runtime-Configurable Thresholds

All ML thresholds (EAR, MAR, similarity) are adjustable at runtime via the Settings screen — no rebuild needed. Values persist in MMKV with getter-priority: MMKV → .env → hardcoded default.

🛡️ Error Boundary Protection

The camera/ML pipeline is wrapped in a React Error Boundary. If the native TFLite module crashes, the app shows a safe fallback screen instead of force-closing.

Scalability & Sustainability

Multi-Device Fleet

  • Each device has a permanent UUID — AWS knows which tablet sent which records
  • Batch sync is idempotent — duplicate POSTs are safe to retry
  • Supports unlimited local employees; cosine search is O(N × 128)

Lighting Adaptability

  • MobileFaceNet trained with aggressive brightness/contrast augmentation
  • Works in harsh sunlight, dim indoor, and shadow conditions
  • Front + back camera fallback for devices with only rear cameras

Demographic Inclusivity

  • Validated against Indian face datasets with diverse skin tones
  • Landmark model handles glasses, masks (partial), facial hair
  • Threshold tuning per deployment region via Settings screen

Future-Ready Architecture

  • Model files are hot-swappable — update .tflite without code changes
  • Hook-based React architecture — easy to extend to iris or voice
  • iOS-ready — same TFLite models work on Apple's CoreML via the bridge
